# 키워드 정규화 → 탐색 네트워크 작업 기록 (2026-11-10 ~ 11)

> 한 줄 요약: "같은 키워드를 합치는 정규화"에서 출발해, **합치지 않고 관계로 연결하는 탐색 네트워크**로 방향을 정리했고, 작품 간 경로를 돌려주는 오프라인 프로토타입까지 만들었다. DB는 한 번도 변경하지 않았다.

## 1. 배경과 목표

- 대상: KMDb + TMDb 키워드 약 19,444개.
- 처음 목표: 같은 개념의 키워드를 합치기(번역어, 철자 변형, 약어 등). 단, **관련만 있는 키워드는 합치지 않는다.**
- 제약: 잘못 합치면 작품 연결 그래프가 오염되므로 보수적으로. 완벽을 목표로 하지 않는다.
- 파이프라인 원칙: **코드·규칙·외부 지식 먼저, LLM은 애매한 소수만.**
- 어제 중간에 정해진 방향: 합치지 않고, **키워드·개념을 관계로 연결한 탐색 네트워크**를 만든다.

## 3. 구조적 발견 (왜 한·영 쌍이 안 잡혔나)

- 기존 규칙은 "독립 신호 2개 이상"이어야 자동 승인했는데, E5 생성 신호는 1개로만 쳤다.
- 공출현(같은 작품에 같이 붙음)은 **1:1로 맞춘 작품 2,283편에서만** 계산돼서 한·영 쌍 대부분이 신호 없음이었다. 같은 언어 쌍 136,313개는 공출현이 전부 비어 있었다.
- 결과적으로 한·영 번역 쌍은 구조적으로 자동 승인에 도달하기 어려웠다.
- 해결: **후보 선별(재현율)과 SAME 승인(엄격)을 분리**. 공출현은 작품 단위(DB 병합 작품)로 다시 계산해 보조 신호로만 사용했다.

## 5. Wikidata(QID) 평가

- DB `entity` 테이블에 QID 컬럼은 있으나 현재 100개 엔티티 중 QID가 있는 것은 없음. 지금까지 QID 작업은 모두 파일 기반.
- 기존 B등급 조건("경쟁 exact QID 없음")은 영어 단어에서는 거의 만족 불가(영화·밴드 이름이 겹침).
- **200쌍 파일럿** (신규 조회, 사용자가 맥에서 실행):
  - QID 라벨 일치 53쌍 → SAME 43 / NOT_SAME 2 / UNSURE 8 (높은 정확도)
  - 후보가 충돌하는 쌍 → NOT_SAME 40 / SAME 9 / UNSURE 11
  - 증거 부족 쌍 → NOT_SAME 46 / SAME 28 / UNSURE 14
  - 결론: **검색 실패·충돌을 NOT_SAME으로 처리하면 안 된다.** 현재 캐시는 용어의 약 5%만 덮음.
- 정정: 이전에 "맨홀 등이 type 오탐으로 막혔다"고 한 것은 오독이었다. `hard_flags` 열은 검색에 걸린 모든 후보 QID를 합친 값이라 영화·밴드 항목의 플래그까지 섞여 있었고, 실제 선택 QID에는 type 플래그가 없었다.

## 6. 코드 자동 SAME 규칙 실험 (AUTO / ASSISTED / HOLD)

**3단계 정의**
- AUTO_SAME: 코드 근거만으로 자동 적용 가능
- ASSISTED_SAME: 근거는 강하지만 추가 판단(LLM 등) 필요
- REVIEW/HOLD: 근거 부족 또는 충돌 → 자동 병합하지 않음 (사람 필수 대기열 아님)

**신규 AUTO 규칙(v1.2)**

| 규칙 | 근거 | 범위 |
|---|---|---|
| N1 QID + translit | 한영 라벨이 같은 깨끗한 Wikidata 항목 + 한글 자음 골격 = 영어 자음 골격 | 한영 외래어 |
| N2 QID + 단어별 조합 | 위 QID + 단어 단위 대응 + 공출현 | 한영 복합어 |
| N3 QID + 공출현 | 위 QID + 같은 작품에 두 키워드 동시 부착 | 한영 일반 |
| N5 철자 변이 + QID | 한 음절 치환 + 같이 안 나옴 + 두 철자가 한 Wikidata 항목의 라벨/별칭 | 같은 언어 한국어 |
| (강등) N4 translit + 공출현 | false friend·모음 소실 오류 → ASSISTED로 강등 | |

**원칙:** QID만, translit만, 공출현만, E5만 같은 **단일 신호는 절대 AUTO가 되지 않는다.**

**결과**

| 구분 | v1.0 | v1.2 |
|---|---|---|
| 1,861쌍 안 신규 AUTO | 135쌍 (SAME 70 / UNSURE 2 / 미판정 63) | 106쌍 (판정 51 / 미판정 55) |
| 전체 후보 308,625쌍에 적용 | — | **142쌍** |
| 기존 코드 SAME 53쌍 유지 | 53/53 | 53/53 |
| 숫자·엔티티 충돌 1,811쌍 승격 | 0 | 0 |
| 판정된 AUTO 중 NOT_SAME | 0 | 0 (95% 신뢰 상한 7%) |

**발견한 오류 유형과 수정 (사람이 쌍을 하나씩 승인하지 않고 규칙을 고침)**

| 오류 | 예시 | 조치 |
|---|---|---|
| ㅡ↔ㅣ 혼동 | 섹스코미디/섹시코미디 | 혼동 집합에서 제외 |
| 3글자 골격 충돌 | 엄마와아들/mother | 3글자 골격은 4음절 이하만 허용 |
| 파생형 | 마라토너/marathon | 개음절 + 영어 자음 종결이면 제외 |
| 모음 소실·false friend | 타임리프/time loop, 펜션/pension | N4를 ASSISTED로 강등 |
| **철자 규칙의 전체 후보 폭주** | 납치/넙치, 모녀/마녀, 아빠/오빠 (172건, 대부분 다른 단어) | N5는 QID 증거 필수로 변경 |
| 규칙으로 못 잡는 것 | 여고생/high school, 성형외과/plastic surgery | 기록만 (Wikidata 라벨 문제) |

> 교훈: **미리 걸러진 소수 쌍에서 잘 되던 규칙이 전체 후보에서는 틀릴 수 있다.** 반드시 전체 후보에 재적용해 확인해야 한다. 일부 수정은 관찰된 사례에서 만든 사후 규칙이라 독립 데이터 검증 전까지는 실험 상태다.

**지표 (서로 분리해서 측정)**

| 지표 | 값 |
|---|---|
| 코드 자동 처리율 | 후보 1,861쌍의 약 8.5% (전체 308,625쌍의 0.05%) |
| LLM 호출률 | 후보의 약 91% (신규 호출이 필요한 쌍 약 498) — 기존과 거의 차이 없음 |
| AUTO 오통합 위험 | 판정된 51쌍 기준 NOT_SAME 0 (상한 약 7%), UNSURE 1 |
| 정규화 커버리지 | AUTO 그룹에 속한 키워드 384개 (2.0%), 그룹 188개 |

> 병목은 규칙이 아니라 **증거 커버리지**다 (Wikidata 캐시가 용어의 약 5%, 한영 사전 없음).

## 7. 방향 전환: 합치기 → 관계로 연결하기

- 이 프로젝트의 목적은 "완벽한 동의어 사전"이 아니라 **서로 다른 작품에 붙은 키워드를 연결해 탐색 경로를 만드는 것**.
- 그래서 EXACT도 병합이 아니라 **엣지(관계)**로 다룬다. 원본 키워드와 출처는 항상 보존한다.
- 관계 유형:

| 유형 | 의미 | 예 |
|---|---|---|
| EXACT | 동일 표기·명백한 번역 | revenge ↔ 복수 |
| CLOSE | 거의 같은 의미 | LLM·사람이 SAME으로 본 쌍 |
| RELATED | 관련은 있으나 의미가 다름 | rival ↔ rivalry |
| BROADER | 상하위 | protest → conflict (Wikidata P279) |

- 관계가 연쇄로 이어지는 것은 문제가 아니라 의도다 (rival → rivalry → competition). 대신 **관계 유형·근거·강도·홉 수**로 점수를 조절한다.
- 관계는 DB에 충분히 저장하고, 결과 수·탐색 범위 제한은 탐색 단계에서 한다.
- E5 단독 후보는 **별도 후보 층**으로 유지하고 기본 탐색에서는 제외한다.

**기존 DB 구조로 담을 수 있는가 (`DB_MAPPING.md`)**

| 필요한 것 | 기존 구조 | 판단 |
|---|---|---|
| 키워드 노드, 번역·별칭 | `entity`(KEYWORD) + `entity_alias` | 가능 |
| 키워드↔작품 | `content_keyword` + `content_entity` | 가능 (단 link_role에 'keyword' 값 없음, `subject`를 빌려 쓰지 않기로 함) |
| 키워드↔키워드 관계 | `entity_relation` (BROADER/RELATED 등) | 부분 가능 |
| 관계 강도·세부 유형 | 없음 | 부족 (당장 스키마 변경 대신 탐색 코드의 기본 가중치 사용) |
| 자동 관계의 탐색 반영 | `next_hop_eligible`은 verified + checked일 때만 | 자동 관계를 전부 verified로 표시하는 식의 우회는 하지 않기로 함 |

## 8. 오프라인 네트워크 실험 (관계 층 추가 전후 비교)

- 작품 43,601편 중 키워드가 하나라도 있는 작품 20,351편. **키워드 없는 작품 23,250편(53%)은 어떤 관계 층으로도 연결되지 않는다** (대부분 KMDb 영화).
- 엣지 6,565개: EXACT 149, SAME(사람 21 + LLM 525) 546, RELATED 계열 약 300, Wikidata 상위 개념 916, 대조군(E5 단독) 4,647.
- 시나리오(누적): S0 원본 → S1 +EXACT → S2 +SAME 엣지 → S3 +RELATED/BROADER → S4 대조군 +E5 단독.

| 시나리오 | 새로 연결된 작품 쌍 | 그중 KMDb↔TMDb | 고립 작품 | 단일 키워드 구제 |
|---|---|---|---|---|
| S0 원본 | 0 | 0 | 192 | 0 |
| S1 EXACT | 약 50.1만 (공유 키워드로) | 24.2만 | 192 | 0 |
| S2 +SAME | +16.0만 (1홉) | +8.6만 | 172 | 331 |
| S3 +RELATED/BROADER | 누적 +103.9만 (1홉), +19.1만 (2홉) | +24.8만 | 153 | 633 |
| S4 대조군 | 누적 +133.2만 | +27.3만 | 89 | 3,793 |

**읽을 때 주의**
- 핵심 효과는 **한국어·영어 키워드가 이어져 KMDb 작품과 TMDb 작품이 연결되는 것**.
- 허브(고빈도) 쏠림: S2 증가분의 82.6%가 상위 10개 엣지에서 나옴 (revenge~복수 한 엣지가 7.8만). 연결 쌍 수는 품질 지표가 아니다.
- E5 단독 엣지는 고립 작품을 가장 많이 줄이지만 오지~오지랖, 마왕~마패 같은 노이즈가 섞여 있다 (+ 대조군에 이미 NOT_SAME으로 판정된 쌍 502개가 섞여 있었음을 이후 확인. 그래서 이 수치는 부풀려졌을 수 있음).
- 숫자는 **허브 상한(작품 60개 등)이 걸린 조건에서 집계한 하한 성격**이며 전체 그래프 규모가 아니다.

## 9. 작품 경로 탐색 프로토타입 (오프라인 CLI)

작품 A →(키워드 a — 관계 — 키워드 b)→ 작품 B 형태로 경로를 돌려준다. 1홉, 2홉 지원, 3홉은 보류.

```bash
cd term_dictionary/runs/impact_20261109/policy_eval/network_exp/prototype
python3 explore.py --content "올드보이" --max-hops 1 --top 15
python3 explore.py --content "변호인" --max-hops 2 --only-hops 2 --top 6 --json out.json
python3 explore.py --stats --sample 300      # 시작 작품 300개 표본 통계
```

- 결과 항목: 작품명·연도·유형·출처, 시작·끝 키워드(원문)와 키워드 출처, 관계 유형·가중치·근거·출처(provenance), 홉 수, 경로 점수, 같은 작품으로 가는 다른 경로 수, 한영 교차 여부.
- 점수(미튜닝): `엣지 가중치 곱 × 0.7^(홉−1) × 1/(1+log10(최대 키워드 df))`.
- 구조 가드: BROADER 두 개를 잇는 2홉은 상향 체인만 허용 (추상 부모를 거치는 엉뚱한 경로 차단, 예: protest → conflict → 해전). 이 가드로 2홉 결과 수 중앙값이 109 → 69.

**동작 확인 (표본 300개 시작 작품)**
- 새 작품이 나오는 비율: 80% (결과 수 중앙값 57.5, 2홉 포함 69)
- 상위 10개 중 한영 교차 비율: 약 49%
- 잘 되는 예: alcoholism → 알코올중독(CLOSE)으로 한국어 작품 연결, anti-capitalist → activist → 활동가
- 보이는 문제: `hammer ~ 햄` 같은 약한 엣지, `여고생 ~ high school` 같은 알려진 오류 엣지가 경로로 번짐

## 10. 번역·관계 사전 확장 계획

**현재 커버리지**
- 키워드 노드 19,386 (영어 4,796 / 한국어 14,590).
- 영어 키워드 중 한국어 번역이 연결된 것: **669개 (14%)**, 부착 횟수 기준 29.7%.
- 영어 키워드는 빈도가 집중: 상위 100개 = 부착 38%(연결 35개), 상위 300개 = 55%, 상위 1,000개 = 76%. 상위 1,000개만 연결해도 대부분 확보.

**기존 데이터로 추가 가능한 소스**

| 소스 | 영어 후보 | 신규 | 비고 |
|---|---|---|---|
| Wikidata 캐시 한국어 라벨·별칭 | 라벨 420 / 별칭 233 | 258 | 번역·별칭. '다른 것(P1889)' 정보로 동음이의 차단 가능 |
| KMDb·TMDb 병렬 작품 정렬 | 211 | 152 | 번역이 아니라 관련 개념이 섞임 → 관계 후보로만 |
| translit 전 노드 | 639 | — | **쓸 수 없음** (LGBT~헬리콥터 등 충돌). 후보 생성과 함께일 때만 |

| 복합어 포함 | 영어 935쌍 / 한국어 5,615쌍 | — | 관련·상하위 후보 (복수 ⊃ 복수극) |

- 후보를 모두 합쳐도 영어 후보 1,215개 (신규 871), 확정이 아니며 부착 기준 커버리지 상한은 약 55%.
- 미커버 영어 3,256개, 상위 300개 중 124개 (thriller, romcom, investigation, k-pop, martial arts 등) — 일반어는 기존 데이터로 채울 수 없음.

**이번 주 구축 순서(제안)**
1. 사전 v0 파일 스키마 확정 + 기존 자산 이관 (원본 보존, 번역·별칭은 별도 행)
2. Wikidata 캐시의 한국어 라벨·별칭 반영
3. 복합어·병렬 작품·E5 후보를 증거 조합별로 CLOSE/RELATED/candidate 등급화
4. 상위 영어 키워드 중 미커버 목록(갭) 확정
5. (승인 필요, 선택) 갭 번역에 LLM 사용 — 상위 700~1,000개, 약 $8~11 추정, 결과는 쌍 단위 원장에 llm_only로 저장
6. 사전 확장 전후로 프로토타입 비교 (같은 5작품 + 표본 300)

**줄거리 검색 활용 원칙**
- 번역어·별칭을 줄거리 검색 후보에 사용하되, **줄거리에서 단어가 발견돼도 작품의 확정 키워드로 등록하지 않는다.** 근거 유형(코드, Wikidata, 병렬 작품, E5, LLM)을 구분해 저장한다.
- 줄거리 매칭 자체는 다음 단계.
