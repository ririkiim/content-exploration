# 엔터티 정규화 및 관계 기반 작품 탐색

## 1. 프로젝트 목적과 설계 원칙

영화·드라마·도서를 인물, 사건, 장소, 시대, 주제 등의 공통 개념으로 연결하는 탐색 시스템을 개발한다.

KMDb, TMDb, 도서 데이터 등 서로 다른 출처에서 수집한 키워드에는 다음과 같은 문제가 있다.

- **표현 차이:** `AI`와 `인공지능`처럼 같은 개념이 서로 다른 키워드로 저장된다.
- **의미 관계:** `작곡가`와 `음악가`처럼 서로 다른 개념이지만 상위·하위 관계가 존재한다.
- **시대 표현:** `일제시대`와 `일제강점기`처럼 같은 시대를 다르게 표현한다.
- **과도한 연결:** `예술가`, `사회`처럼 범위가 넓은 개념을 무조건 사용하면 관련성이 낮은 작품까지 연결된다.

따라서 키워드의 동일성, 개념 간 관계, 실제 작품 연결을 단계적으로 처리한다.

### 핵심 설계 원칙

1. **원본 키워드를 보존한다.** 같은 개념으로 판단되더라도 키워드를 물리적으로 합치지 않고 `SAME` 간선으로 연결한다.
2. **관계 유형과 신뢰도·상태를 분리한다.** `SAME`, `BROADER`, `RELATED` 등의 관계 유형과 후보·보류·채택·거절 상태는 별도로 관리한다.
3. **거절된 후보도 기록한다.** 같은 오류가 반복되지 않도록 판단 근거와 변경 이력을 보존한다.
4. **유사도만으로 관계를 확정하지 않는다.** 임베딩과 LLM은 후보 생성 및 보조 판단에 활용하며, `SIMILAR`도 검증을 거쳐 승격된 후보에만 사용한다.
5. **탐색 설정은 실험으로 결정한다.** 관계 가중치, 임계값, 탐색 hop 제한은 실험 후 버전별 설정으로 관리한다.

이 문서는 **키워드 기반 엔터티 정규화와 관계 확장 경로**를 다룬다. 주제·시놉시스 기반 탐색 경로(B)는 별도로 설계한다.

## 2. 전체 처리 흐름

```text
KMDb / TMDb / 도서 키워드
             │
             ▼
       키워드 정규화
             │
             ▼
       동일 개념 후보 생성
       ├─ 표기·규칙 기반
       ├─ 다국어 임베딩
       └─ Wikidata QID 후보
             │
             ▼
       SAME 후보 판단·관리
       ├─ SAME / EXACT
       ├─ BROADER / RELATED 후보
       └─ 보류 / 제외
             │
             ▼
       원본 키워드 및 후보 보존
             │
       ┌─────┴──────────────┐
       ▼                    ▼
  시간 표현 규칙 처리    Wikidata 관계 확장
  ├─ 연도·연대·세기      ├─ QID 매칭
  ├─ 명명된 시대         ├─ P279 / P361
  ├─ 기간 포함·중첩      ├─ 위험 관계 필터링
  └─ 시대 관계 후보      └─ 중복 관계 분석
       │                    │
       └─────────┬──────────┘
                 ▼
        관계 후보 및 근거 관리
                 │
                 ▼
         작품 연결 영향도 분석
                 │
                 ▼
         품질 평가·사용 기준 결정
                 │
                 ▼
           관계 데이터 구성
                 │
                 ▼
          작품 간 경로 탐색
```

현재는 후보 생성, 관계 분석, 영향도 측정, 검토 표본 생성까지 진행했다.

최종 관계 허용 기준과 실제 탐색 기능 적용은 다음 단계다. 분석 결과는 CSV·JSON 등 중간 산출물로 관리하며 데이터베이스에 자동 반영하지 않는다.

수동 검토는 모든 운영 관계에 적용하는 필수 절차가 아니라 **후보 생성 규칙의 품질을 평가하기 위한 표본 검증**으로 사용한다.

## 3. 키워드 정규화 및 SAME 후보 생성

### 3.1 후보 생성 방법

KMDb와 TMDb 등의 키워드 약 1.9만 개를 정규화하고, 같은 개념일 가능성이 있는 키워드 쌍을 탐색했다.

| 방법 | 역할 |
|---|---|
| 표기 정규화 | 띄어쓰기·구두점 등 표현 차이 처리 |
| 규칙 기반 비교 | 약어, 숫자 충돌, 표기 변형 확인 |
| 다국어 임베딩 | 의미적으로 유사한 키워드 탐색 |
| Wikidata QID | 외부 지식베이스의 개념 식별자 참고 |
| LLM | 불확실한 후보의 보조 검토 |

임베딩에는 `multilingual-e5-base`를 사용했으며, 후보 탐색 설정은 `top-k=5`, 최소 유사도 `0.80`이었다.

전체 후보는 약 30.8만 쌍 규모였다. 다만 후보의 유사도가 높다는 사실만으로 동일 개념이라고 판단하지 않는다.

### 3.2 후보 판단 기준

| 관계 | 의미 | 예시 |
|---|---|---|
| `SAME / EXACT` | 실질적으로 같은 개념 | AI ↔ 인공지능 |
| `BROADER` | 상위·하위 개념 | 작곡가 → 음악가 |
| `RELATED` | 관련은 있지만 동일하지 않은 개념 | 서로 관련된 주제 |
| 보류 / 거절 | 근거가 부족하거나 부적절한 후보 | 납치 ↔ 넙치 |

임베딩에서는 `납치`와 `넙치`처럼 의미가 다르지만 유사하게 나타나는 후보가 발생할 수 있다.

따라서 명확한 규칙과 식별자 근거를 우선하고, 임베딩과 LLM은 보조적으로 활용한다.

특히 문자열·별칭 일치로 발견한 Wikidata QID는 해당 문자열 매칭과 독립된 검증 근거로 간주하지 않는다.

### 3.3 기존 실험 결과

| 항목 | 결과 |
|---|---:|
| 정규화 키워드 | 약 19,442개 |
| 전체 후보 쌍 | 약 30.8만 쌍 |
| 고유사도 후보 LLM 재검토 | 150쌍 |
| 판단 보류 | 29쌍 |
| 서로 다른 개념으로 분류 | 6쌍 |
| 규칙·정규화·숫자 충돌 등으로 선제 필터링 | 약 1,800쌍 |

A등급 SAME 후보 51쌍을 가상 적용했을 때 신규 연결 2,825건이 발생했다.

이 중 약 76%가 KMDb와 TMDb 사이의 연결이었고, 상위 5개 후보가 전체 증가량의 약 91%를 차지했다.

즉, 소수의 SAME 후보가 전체 작품 연결 결과에 큰 영향을 줄 수 있으므로 **연결 증가량보다 개념 동일성의 정확성을 우선**한다.

## 4. 시대(TIME_PERIOD) 처리

시대는 일반 키워드와 달리 시작·종료 시점을 이용해 관계를 계산할 수 있으므로 별도의 규칙 기반 경로로 처리한다.

### 4.1 시대 표현 구분

시대 파서 v1에서는 연도·연대·세기 등 숫자형 시간 표현을 중심으로 처리한다.

| 유형 | 예시 | 파싱 결과 |
|---|---|---:|
| 연도 | 1987년 | 19개 |
| 연대 | 1990년대 | 27개 |
| 세기 | 20세기 | 23개 |
| 명명된 시대 | 조선시대 등 | 5개 |
| **합계** | | **74개** |

전체 키워드 약 19,442개 중 74개를 파싱했고, 32개는 자동 처리에서 제외해 보류했다.

숫자 표현의 파싱 규칙은 v1에서 범위를 고정했다.

반면 **명명된 시대는 별도 데이터 파일에서 시대명, 상위 시대, 시작·종료 시점, 출처, 상태를 관리하고 확장**한다.

따라서 파서에서 처리한 명명된 시대 5개가 전체 역사 시대 데이터의 범위를 의미하지는 않는다.

복합 표현이나 사건형 시간 표현은 자동 관계 생성 대상에서 제외한다.

### 4.2 시대 관계 판단 기준

| 관계 | 판단 기준 | 예시 |
|---|---|---|
| `SAME` | 같은 시대를 가리키는 표현 | 1980s ↔ 1980년대 |
| `SAME` | 동일한 명명 시대의 다른 표현 | 일제시대 ↔ 일제강점기 |
| `TEMPORAL` | 숫자 시간 범위의 완전 포함 | 1990년대 ⊂ 20세기 |
| `TEMPORAL` | 숫자 연도가 명명된 시대 범위에 완전히 포함 | 특정 연도 → 명명된 시대 |
| `BROADER` | 명명된 시대의 개념적 상하위 관계 | 조선초기 ⊂ 조선시대 |
| `RELATED` + `temporal_overlap` | 시간 범위가 일부 중첩 | 삼국시대 ↔ 신라시대 |

숫자 연도가 명명된 시대에 포함되는 관계에는 `named_period_range` 근거를 남긴다.

부분 중첩 관계에는 `temporal_overlap` 근거를 기록한다. 역사 시대의 경계와 정의가 복잡한 경우에는 자동 확정하지 않는다.

**시간 범위가 일부 겹친다는 이유만으로 SAME 처리하지 않는다.**

또한 시간 범위에 따른 포함 관계와 역사 시대의 개념적 상하위 관계는 구분한다.

### 4.3 시대 SAME 실험

동일한 역사 시대를 가리키는 표현을 SAME 간선으로 연결한다고 가정하고, 신규 작품 연결을 분석했다.

| SAME 후보 | 신규 고유 작품 쌍 |
|---|---:|
| 일제시대 ↔ 일제강점기 | 403개 |
| 이조시대 ↔ 조선시대 | 332개 |
| **합계** | **735개** |

735개는 **A0(동일 키워드 ID 공유, SAME 미반영) 기준 대비 신규 작품 쌍**이다.

동일 시대 표현을 연결하는 것만으로도 작품 탐색 범위를 확장할 가능성이 있음을 확인했다. 다만 실제 탐색 품질을 검증한 결과는 아니다.

### 4.4 인물·사건과 시대 연결

시대 탐색은 시간 표현끼리의 관계에만 한정되지 않는다.

인물이나 사건이 특정 시대와 관련되는 경우 `RELATED` 관계로 연결하고, `person_in_period`, `event_in_period` 등의 근거 유형을 구분해 보존하는 방향으로 설계했다.

이 경로는 인물·사건 엔터티가 먼저 공급되어야 하며, 실제 작품 탐색에서는 별도 인수 테스트로 확인할 예정이다.

## 5. Wikidata 기반 관계 확장

### 5.1 관계 확장 목적

SAME 간선은 동일한 개념의 표현을 연결하지만, 서로 다른 개념 사이의 관계까지 표현하지는 못한다.

예를 들어 `바이올리니스트`와 `음악가`는 동일한 개념이 아니지만 상위·하위 관계를 통해 연결할 수 있다.

이를 위해 기존 Wikidata 캐시를 활용해 개념 간 관계를 추출했다.

### 5.2 키워드와 QID 매칭

정규화된 키워드 약 19,442개를 기존 Wikidata 캐시와 비교했다.

| 근거 | 의미 |
|---|---|
| `LABEL_KO` | 한국어 레이블 일치 |
| `LABEL_EN` | 영어 레이블 일치 |
| `ALIAS_KO` | 한국어 별칭 일치 |
| `ALIAS_EN` | 영어 별칭 일치 |

여러 매칭 근거가 존재할 수 있으며, `match_evidence`에 `|`로 구분해 기록한다.

후보별로 키워드 ID, QID, 레이블, 설명, 매칭 근거, 위험 플래그를 보존한다.

| 항목 | 결과 |
|---|---:|
| 정규화 키워드 | 19,442개 |
| 기존 Wikidata 캐시 QID | 8,994개 |
| QID 후보를 발견한 키워드 | 2,533개 |
| 후보 발견 비율 | 13.03% |

13.03%는 캐시에서 후보를 발견한 비율이며, **매핑 정확도나 최종 관계 연결 성공률을 의미하지 않는다.**

### 5.3 관계 추출

Wikidata의 두 가지 속성을 분석했다.

| 속성 | 의미 | 예시 |
|---|---|---|
| `P279` | 하위 개념 → 상위 개념 | 바이올리니스트 → 음악가 |
| `P361` | 부분 → 전체 | 부분 개념 → 전체 개념 |

두 키워드의 QID 사이에 해당 관계가 존재하면 관계 후보로 수집한다.

관계 방향과 원본 QID, 속성, 근거를 보존하며, P279와 P361을 동일한 관계로 취급하지 않는다.

P361을 내부 관계 유형인 PART_OF로 어떻게 반영할지는 아직 확정하지 않았다.

### 5.4 초기 분석 결과

| 항목 | 결과 |
|---|---:|
| 캐시에 존재하는 전체 관계 | 7,228개 |
| 양쪽 QID가 매칭 후보에 존재하는 관계 | 751개 |
| └ P279 | 625개 |
| └ P361 | 126개 |
| 초기 허브 제한으로 제외한 관계 | 150개 |
| 초기 분석의 잠재 작품 쌍 | 460,362개 |

초기 분석에서는 `예술가`, `사회`, `사업`처럼 범위가 넓은 개념이 지나치게 많은 작품을 연결하는 문제가 나타났다.

따라서 Wikidata에 관계가 존재한다는 이유만으로 모두 허용하지 않고, **매핑 신뢰도와 관계의 범위, 실제 작품 연결에 미치는 영향**을 추가로 분석했다.

## 6. 관계 후보 정제 및 중복 분석

### 6.1 집계 단위 구분

분석 결과를 해석할 때는 다음 세 단위를 구분해야 한다.

- **QID 관계:** Wikidata의 두 개념 사이의 관계
- **키워드 간선:** QID 관계가 실제 키워드 ID 사이로 확장된 연결
- **관계 근거 행:** 해당 간선을 뒷받침하는 QID·속성 정보

예를 들어 `음악가`와 `musician`이 동일 QID를 가리키는 경우 SAME 후보가 될 수 있다.

반면 `composer → musician`은 서로 다른 QID 사이의 상위·하위 관계다.

### 6.2 정제 결과

| 분석 항목 | 결과 |
|---|---:|
| 초기 QID 관계 후보 | 751개 |
| Strict 조건으로 별도 집계한 QID 관계 | 247개 |
| 후속 필터링을 통과한 키워드 간선 | 568개 |
| 해당 간선의 QID 관계 근거 행 | 571개 |
| 고유 QID 관계 | 243개 |

이 숫자는 모두 같은 단위의 순차적인 감소 결과가 아니다.

특히 247개는 strict 조건에서 집계한 QID 관계이고, 568개는 실제 키워드 사이의 간선이다.

568개 키워드 간선을 `(source_qid, property, target_qid)` 기준으로 묶으면 243개 고유 QID 관계가 된다.

247개와 243개의 차이를 만드는 정확한 필터 조건은 관련 스크립트를 대조해 확인할 예정이다.

### 6.3 동일 QID 관계의 중복 확장

하나의 QID에 여러 키워드가 매칭되면 동일한 QID 관계가 여러 키워드 간선으로 확장될 수 있다.

예를 들어 `sibling`에 `형`, `오빠`, `언니` 등 여러 키워드가 연결될 수 있다.

이때 개별 키워드가 실제로 같은 개념인지 확인하지 않으면 잘못된 관계가 여러 작품으로 확대될 수 있다.

분석 결과 **243개 고유 QID 관계 중 152개가 여러 키워드 간선으로 확장**됐다.

중복 자체가 반드시 오류는 아니지만, QID 관계의 타당성과 각 키워드의 매핑 정확도를 별도로 확인해야 한다.

또한 `작곡가 → 음악가 → 예술가`처럼 여러 경로로 동일한 상위 개념에 도달하는 전이적 중복은 향후 탐색 그래프 구성 시 처리할 예정이다.

## 7. 작품 연결 영향도 분석

### 7.1 분석 기준

관계 후보가 실제 작품 사이에 얼마나 많은 연결을 생성하는지 분석했다.

기존 연결을 판단하는 기준으로 A0를 사용했다.

**A0는 동일한 `staging_id` 키워드를 공유하는 작품 쌍이다.**

아직 최종 SAME 간선을 반영한 기준은 아니므로, 이후 SAME 관계를 적용한 상태에서 다시 비교할 필요가 있다.

### 7.2 연결 결과

| 항목 | 결과 |
|---|---:|
| 관계 분석 대상 작품 | 3,809개 |
| 잠재적 작품 쌍 | 59,642개 |
| A0 기준 기존 연결 | 7,309개 |
| A0 기준 신규 연결 후보 | 52,333개 |

52,333개는 **검증되지 않은 잠재적 신규 작품 쌍**이다.

관계가 정확한지, 실제 작품들이 의미적으로 관련되는지, 사용자에게 유용한 탐색 결과인지는 아직 검증하지 않았다.

### 7.3 관계별 기여도

| 관계 범위 | 중복 제거한 신규 작품 쌍 | 전체 대비 |
|---|---:|---:|
| 상위 5개 키워드 관계 | 10,123개 | 19.34% |
| 상위 30개 키워드 관계 | 26,781개 | 51.17% |
| 전체 관계 | 52,333개 | 100% |

상위 30개 키워드 관계만으로 전체 신규 연결 후보의 절반 이상을 설명한다.

따라서 영향도가 큰 관계를 우선 검토하되, **연결 수가 많다는 이유만으로 관계가 정확하거나 유용하다고 판단하지 않는다.**

## 8. 매핑 오류와 관계 품질 분석

### 8.1 키워드 ↔ QID 매핑 문제

키워드가 의도한 의미와 다른 Wikidata 항목에 연결될 수 있다.

| 키워드 | 매칭된 개념 | 의심되는 문제 |
|---|---|---|
| 심리 | spirit | 심리와 영혼의 의미 불일치 |
| 스승 | sensei | 의미 범위 차이 |
| 병 | soldier | 다의어로 인한 의미 충돌 |
| 주장 | brewery | 일반적인 주장과 맥주 주조장의 의미 충돌 |
| 형·오빠·언니 | sibling | 구체적인 호칭과 포괄적인 개념의 차이 |

이들은 **오류 가능성이 있는 의심 사례**이며, 전체 매핑에 대한 최종 판정 결과가 아니다.

앞서 조사한 의심 사례 11개는 모두 `ALIAS_KO` 매칭이었지만, 영향도가 높거나 의심스러운 사례를 선별했으므로 전체 매칭을 대표하지 않는다.

### 8.2 QID 관계 자체의 문제

양쪽 키워드가 올바르게 매칭됐더라도 관계 자체가 부적절하거나 탐색에 유용하지 않을 수 있다.

| 관계 | 검토할 문제 |
|---|---|
| filmmaker → photographer | 하위·상위 관계로 적절한가? |
| composer → artist | 관계는 타당하지만 너무 넓지 않은가? |
| violinist → musician | 명확한 직업 계층 관계인가? |

따라서 **매핑 정확도와 관계 타당성을 분리해서 평가**한다.

### 8.3 매칭 근거 분석

`match_evidence`에 `|`로 결합된 복수 근거를 분리해 분석했다.

571개 관계 근거 행에서 나타난 주요 매칭 방식 조합은 다음과 같다.

| Source + Target | 근거 행 |
|---|---:|
| ALIAS_KO + LABEL_EN | 98 |
| ALIAS_KO + LABEL_KO | 97 |
| LABEL_EN + LABEL_KO | 81 |
| ALIAS_EN + ALIAS_KO | 58 |
| LABEL_KO + LABEL_KO | 53 |
| ALIAS_EN + LABEL_KO | 52 |
| ALIAS_EN + LABEL_EN | 44 |
| ALIAS_KO + ALIAS_KO | 42 |

전체 571개 근거 행 중 295개(51.7%)에 `ALIAS_KO`가 포함됐다.

이는 **근거 행 기준 비율**이며, 고유 QID 관계의 비율이나 신규 작품 쌍의 비율, 매핑 오류율을 의미하지 않는다.

별칭 매칭의 비중이 높다는 사실만으로 모두 제외하지 않고, 실제 검토 결과를 바탕으로 사용 기준을 결정할 예정이다.

## 9. 품질 검토 및 관계 사용 기준

### 9.1 검토 단위

검토 대상은 두 가지로 구분한다.

| 검토 대상 | 단위 | 확인할 내용 |
|---|---|---|
| 키워드 매핑 | `(staging_id, QID)` | 키워드와 QID가 같은 개념인가? |
| QID 관계 | `(source_qid, property, target_qid)` | 관계가 타당하고 탐색에 유용한가? |

같은 QID 관계에 속하더라도 개별 키워드의 매핑 정확도는 다를 수 있다.

따라서 대표 키워드 한 쌍을 검토했다고 해서 해당 QID 관계에 속한 모든 키워드 매핑이 검증된 것은 아니다.

### 9.2 현재 검토 표본

243개 고유 QID 관계 중 50개를 선정했다.

| 구분 | 개수 | 목적 |
|---|---:|---|
| TOP | 25개 | 영향도가 큰 관계의 오류 확인 |
| RANDOM | 25개 | 상위 관계 외의 다양한 사례 확인 |
| **합계** | **50개** | 주요 오류 유형과 활용 가능성 검토 |

TOP은 해당 QID 관계에 속한 키워드 간선 중 가장 높은 영향도 순위를 기준으로 선정했다.

RANDOM은 나머지 관계에서 고정 시드 `42`로 추출했다.

현재 `22_relation_review_sample.csv`에는 **QID 관계별 대표 키워드 한 쌍**이 들어 있다.

관계 타당성은 이 QID 관계 단위로 평가하고, 키워드 매핑 정확도는 선정된 관계에 속한 고유 `(staging_id, QID)` 쌍을 별도로 펼쳐 검토할 예정이다. 이 별도 매핑 검토표는 아직 생성하지 않았다.

현재 표본은 탐색적 검토용이며, `ALIAS_KO` 포함 여부, 키워드 길이, 빈도, 관계 속성에 따라 층화한 대표 표본은 아니다.

### 9.3 검토 항목

현재 표본 CSV에는 다음 항목을 사용한다.

| 항목 | 의미 | 판정값 |
|---|---|---|
| `source_mapping_review` | 대표 출발 키워드의 QID 매핑 | 맞음 / 틀림 / 모호 |
| `target_mapping_review` | 대표 도착 키워드의 QID 매핑 | 맞음 / 틀림 / 모호 |
| `relation_review` | QID 관계의 타당성과 활용 가능성 | 오류 / 타당하지만 약함 / 유용 |

예를 들어 `귀신 → 심리`라는 키워드 관계에서 실제 QID 관계가 `ghost → spirit`이라면, QID 관계 자체는 타당하더라도 `심리 → spirit` 매핑은 잘못됐을 수 있다.

이처럼 매핑 오류와 관계 오류를 구분해 기록한다.

### 9.4 관계 사용 원칙

검토 전에 다음 판단 원칙을 정한다.

1. 잘못되거나 모호한 키워드-QID 매핑은 자동 허용하지 않는다.
2. 관계 자체가 부적절한 QID 관계는 사용을 보류한다.
3. 관계가 타당하더라도 지나치게 포괄적이면 탐색 범위를 제한하거나 보류한다.
4. 별칭 매칭은 매칭 방식만으로 일괄 허용하거나 제외하지 않는다.
5. 판단 기준이 변경되면 변경 이유와 근거를 기록한다.

향후 `ALIAS_KO` 매칭의 정확도를 다른 매칭 방식과 비교할 필요가 있다면 별도 층화 표본을 구성한다. 이때 매칭 방식, 키워드 길이, 키워드 빈도(df), P279/P361 속성 등을 구분해 평가한다.

현재는 검토 표본 생성까지 완료했으며, 수동 판정 결과와 최종 자동 허용 기준은 아직 확정되지 않았다.
