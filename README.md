              │                       │

              │                       │
              │                대표 판본 선정
              │                       │
              │             content / book_edition 적재

              │                       │
              └───────────┬───────────┘
                          ▼
                    콘텐츠 정보 확보
                          │
                          ▼
                  기존 관계 데이터 확인
                          │
              ┌───────────┴───────────┐
              ▼                       ▼
          기존 관계 있음           신규 관계 필요

              │                콘텐츠 정보 전처리

- 영화·드라마는 기존 PostgreSQL 카탈로그를 활용한다.
- 도서는 YES24에서 ISBN 후보를 검색하고, 정보나루에서 상세정보를 확보한다.
- 사용자가 직접 선택한 도서는 작품 식별 및 대표 판본 선정 후 적재한다.
- 추천 후보 도서는 2차 LLM 관계 검증에서 승인된 경우에만 적재한다.
- 기존 관계와 설명이 존재하면 저장된 결과를 재사용한다.
- LLM은 신규 관계 생성 및 검증이 필요한 경우에만 호출한다.

## 2. 도서 작품·판본 매칭 파이프라인

```text
             [도서 검색 요청]
                    │
                    ▼
              YES24 제목 검색
                    │
                    ▼
               ISBN 후보 확보
                    │
                    ▼
              후보 분류 및 제외
                    │
                    ▼
              대표 자격 확인
                    │
                    ▼
            정보나루 ISBN 상세 조회
                    │
                    ▼
              책소개 유효성 확인
                    │
                    ▼
              대표 판본 1개 선정
                    │
                    ▼
               작품·판본 매칭
                    │
                    ▼
               PostgreSQL 적재
                    │
             ┌──────┴──────┐
             ▼             ▼
           content     book_edition
           (작품)       (대표 판본)
                    │
                    ▼
              LLM 관계 추출
                    │
                    ▼
              2차 LLM 검증
                    │
                    ▼
           필요시 YES24 목차 활용
              (관계 근거 보강)
```

- YES24는 도서 검색 및 ISBN 후보 확보에 활용한다.
- 정보나루는 도서 상세정보 확보 및 적재 기준 데이터로 사용한다.
- YES24 책소개·목차 원문은 기본적으로 DB에 적재하지 않는다.
- 목차는 관계 검증에 추가 근거가 필요한 경우 선택적으로 활용한다.
- YES24 목차의 외부 LLM 전달 가능 여부는 이용 조건 확인이 필요하다.
- 실제 적재 시점은 사용자 선택 도서와 추천 후보 도서를 구분한다.

## 3. 신규 ISBN 작품·판본 매칭

```text
                  신규 ISBN
                      │
                      ▼
        기존 book_edition에 ISBN 존재?
                      │
             ┌────────┴────────┐
             ▼                 ▼
            YES                NO
             │                 │
             ▼                 ▼
       기존 content_id     제목 + 원저자 정규화
            재사용               │
                                ▼
                         기존 작품과 비교
                                │
                  ┌─────────────┼─────────────┐
                  ▼             ▼             ▼
             동일 작품 확인   다른 작품 확인     불확실
                  │             │             │
                  ▼             ▼             ▼
             기존 content_id  신규 content_id  매칭 보류
                  연결           생성        (추가 검증)
```

### 매칭 원칙

- ISBN13을 우선 식별자로 사용한다.
- 동일 ISBN이 존재하면 기존 `content_id`를 재사용한다.
- 신규 ISBN은 제목·원저자 정규화를 통해 기존 작품과 비교한다.
- 동일 작품으로 확인된 판본은 기존 `content_id`에 연결한다.
- 서로 다른 작품으로 확인된 경우에만 신규 `content_id`를 생성한다.
- 동일 작품 여부가 불확실하면 자동 적재하지 않고 매칭을 보류한다.
- 각색본·합본은 일반 판본과 구분하여 별도로 검토한다.

## 4. 대표 판본 선정 기준

대표 판본은 작품을 정확하게 식별하고, LLM 관계 추출에 활용할 수 있는 일반 판본을 기준으로 선정한다.

**제외 → 자격 확인 → 우선순위 비교**의 3단계로 진행한다.

| 단계 | 기준 |
|---|---|
| ① 제외 | 각색본, 합본, 공동저작, 해설서, 필사 노트, 청소년판 등 |
| ② 자격 | 제목·원저자 일치, 유효한 ISBN13, 정보나루 상세 조회 성공 |
| ③ 순위 | 유효한 책소개 → 정보량 → 일반 판본 여부 → 출간연도 → ISBN |

### 4.1. 책소개 유효성

- 책소개가 존재하고 공백 제외 50자 이상
- 수상·판매·홍보 문구만으로 구성된 소개는 제외
- 구체적인 내용 품질은 관계 추출 단계에서 검증
- 50자는 초기 기준이며 테스트 결과에 따라 조정 가능

### 4.2. 판본 관리

- 초기에는 작품당 대표 판본 1개만 적재한다.
- 신규 ISBN 발견 시 기존 작품과의 동일성을 확인한 후 연결한다.
- 기존 대표 판본은 유지하고 필요할 때만 재선정한다.
- 대표 판본 변경은 PostgreSQL 트랜잭션으로 처리한다.
- 대표 변경 시 기존 대표를 해제한 후 신규 대표를 지정한다.
- 대표 선정에서 제외된 판본도 향후 관련 콘텐츠로 활용할 수 있다.
- 제외 사유는 `excluded_reason` 등의 상태값으로 관리할 수 있다.

### 4.3. 다권 작품

- 《토지》처럼 여러 권으로 구성된 작품은 우선 1권 또는 전집 ISBN 하나를 대표로 선정한다.
- 권차별 관리 기능은 추후 구현한다.
- 대표 ISBN의 책소개가 작품 전체를 설명한다고 가정하지 않는다.
- 작품 전체의 주제·인물·사건 정보는 추후 Wikipedia 등으로 보강한다.

## 5. 도서 데이터 활용 원칙

| 데이터 | 출처 | 활용 |
|---|---|---|
| ISBN 후보 | YES24 | 도서 검색 및 판본 식별 |
| 제목·저자·출판사 | 정보나루 | 작품·판본 정보 적재 |
| 책소개 | 정보나루 | LLM 관계 추출 및 검증 |
| 목차 | YES24 | 필요시 관계 검증 보조 |
| 작품 맥락 | Wikidata / Wikipedia | 작품·인물·사건·주제 보강 |

- YES24는 검색 보조 수단으로 활용한다.
- 정보나루에서 확보한 상세정보를 기준으로 DB에 적재한다.
- Wikipedia는 전체 데이터를 적재하지 않고 필요한 작품만 조회한다.
- Wikidata 작품 매칭은 확인 가능한 경우에만 활용한다.
- 위키 정보가 없거나 매칭이 불확실하면 보강 단계를 생략한다.
- 외부 데이터의 저장·재사용·LLM 전달은 각 제공처의 이용 조건을 확인한다.

- YES24 검색 및 ISBN 후보 확보
- 규칙 기반 후보 분류
- 정보나루 ISBN 상세 조회
- 작품·판본 매칭
- 대표 판본 1개 선정
- `content` / `book_edition` 적재
- 기존 작품 및 ISBN 중복 확인
- LLM 관계 추출·검증 파이프라인 연결

### 추후 구현

- 다권 작품의 권차별 관리
- 대표 판본 자동 재선정
- 판본별 책소개 품질 비교
- 대표 판본과 LLM 입력용 판본 분리
- YES24 목차를 활용한 추가 관계 검증
- Wikipedia 기반 작품 전체 맥락 보강

### 추후 개선 사항

- YES24 검색 실패 또는 이용 제한 시 정보나루 `srchBooks`를 대체 검색 경로로 활용

- 추천 후보 도서는 작품 매칭이 불확실하면 적재 및 추천 보류
- 임시 탐색 결과와 확정된 `content_id`를 구분하여 관리
