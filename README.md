# 한영 키워드 통합: E5 기반 후보 탐색 및 평가

> **진행 상태:** E5 후보 생성 및 풀 확장 완료 · 독립 평가 진행 중 · DB 통합 미실행

## 1. 프로젝트 배경 및 목적

본 프로젝트는 영화·드라마·도서에 포함된 키워드를 활용하여 콘텐츠 사이의 관계를 탐색하는 시스템이다.

키워드는 TMDb, KMDb 등 여러 출처에서 수집되기 때문에 동일한 개념이 서로 다른 언어와 표기로 기록되는 문제가 있다.

예를 들어 `로보트`, `로봇`, `robot`은 같은 개념이지만 별도의 키워드로 존재한다. 이를 그대로 사용하면 동일 개념이 서로 다른 엔티티로 분리되어 콘텐츠 간 연결이 누락될 수 있다.

따라서 여러 키워드가 동일한 개념을 나타내는지 식별하고, 동일 개념으로 확인된 표현을 하나의 엔티티와 별칭으로 통합하는 것을 목표로 한다.

### 키워드 통합 원칙

모든 의미적으로 유사한 키워드를 통합하는 것은 아니다.

| 키워드 쌍 | 관계 | 처리 방향 |
|---|---|---|
| 로보트 / robot | 동일 개념 | EXACT 통합 |
| 가정폭력 / domestic violence | 동일 개념 | EXACT 통합 |
| 로봇 / robotics | 대상과 학문 | 별도 개념 |
| 고등학생 / student | 상하위 개념 | 별도 개념 |
| 크리스마스 / 연말연시 | 기념일과 기간 | 별도 개념 |

기본 원칙은 **분리 상태를 유지하다가 동일 개념이라는 충분한 근거가 확보된 경우에만 통합하는 것**이다.

원본 키워드와 데이터 출처, 통합 근거는 보존한다. EXACT가 아닌 관계는 향후 `entity_relation`을 통해 별도로 관리한다.

현재 작업은 후보 생성과 평가 단계이며, 실제 DB 병합은 진행하지 않았다.

## 2. 키워드 통합 파이프라인 및 E5 도입

### 2.1 전체 처리 흐름

```text
TMDb / KMDb 원본 키워드
          ↓
    문자열 정규화
          ↓
  외부 식별자 및 별칭 매칭
    (Wikidata QID 등)
          ↓
   E5 의미 유사도 검색
          ↓
   동일 개념 후보 생성
          ↓
  의미·유형·맥락 검증
          ↓
  EXACT / 비EXACT 구분
          ↓
 entity / entity_alias 통합
```

문자열 정규화는 대소문자, 공백, 표기 차이 등을 비교하기 위한 전처리다. 하지만 정규화만으로 서로 다른 언어의 동일 개념을 모두 찾을 수는 없다.

Wikidata QID와 다국어 레이블·별칭을 활용하면 외부 지식에 기반한 개념 매칭이 가능하다. 그러나 Wikidata에 등록되지 않았거나 별칭이 누락된 표현은 여전히 찾기 어렵다.

이러한 누락을 보완하기 위해 다국어 임베딩 모델인 **`intfloat/multilingual-e5-base`** 를 후보 탐색에 도입했다.

### 2.2 E5의 역할

E5는 한국어와 영어 키워드를 벡터로 변환하고 의미적 유사도를 계산한다.

이를 통해 문자열이 달라도 의미가 가까운 키워드를 후보로 제시할 수 있다.

다만 의미적으로 가깝다는 사실이 동일 개념이라는 뜻은 아니다.

실제 실험에서도 다음과 같은 높은 유사도의 오탐이 발견됐다.

- `마법 ↔ martial arts`: 0.847
- `재수생 ↔ reincarnation`: 0.840

따라서 **E5는 후보 검색에만 사용하고, EXACT 여부는 별도 근거와 검증을 통해 결정한다.**

같은 Wikidata QID가 확인된 경우에도 키워드의 의미 범위와 맥락을 검토할 필요가 있다.

## 3. E5 후보 생성 방법

### 3.1 모델 및 검색 설정

| 항목 | 설정 |
|---|---|
| 모델 | `intfloat/multilingual-e5-base` |
| 입력 접두사 | `query:` |
| 유사도 | 코사인 유사도 |
| 검색 방향 | 한국어 → 영어 / 영어 → 한국어 |
| 검색 범위 | 각 방향 Top-5 |
| 후보 결합 | 양방향 합집합 |
| 유사도 임계값 | 0.80 이상 |
| 보조 지표 | `mutual_best` |

한국어에서 영어를 검색한 결과와 영어에서 한국어를 검색한 결과를 합쳐 후보를 구성한다.

한쪽 방향에서만 검색되는 쌍도 후보에 포함되므로 단방향 검색보다 넓은 범위를 탐색할 수 있다.

`mutual_best`는 두 용어가 서로를 가장 유사한 Top-1 후보로 선택한 경우를 의미한다. 신뢰도를 판단하는 참고 정보지만, 동일 개념을 보장하지는 않는다.

### 3.2 초기 입력 데이터

초기 실험에서는 등장 콘텐츠 수가 21회 이상인 용어 1,112개를 대상으로 했다.

- 한국어: 933개
- 영어: 164개
- 혼합 표현: 15개 (검색 대상 제외)

빈도가 높은 용어부터 실험했지만, 낮은 빈도의 키워드에도 중요한 동일 개념 표현이 존재할 수 있다는 문제가 있었다.

이에 따라 입력 용어의 빈도 기준을 낮추는 풀 확장 실험을 진행했다.

## 4. E5 재현성 검증 및 풀 확장 실험


### 4.1 재현성 검증

기존 ge21 실험을 동일한 조건으로 다시 실행하여 원본 결과와 비교했다.

- 원본: `term_cross_lingual.csv`
- 재실행: `out_ge21.csv`
- 검증 코드: `check_reproduction.py`
- 실행 환경: `manifest_ge21.json`

검증 결과, 원본과 재실행 결과가 파일 수준에서 완전히 일치했고 유사도 점수 차이도 0이었다.

이후 ge6와 ge2의 저장된 후보 집합도 재계산 결과와 비교했으며, 두 경우 모두 차이 0건으로 확인됐다.

따라서 이후 풀 간 비교는 저장 과정의 불일치가 아닌 실제 입력 풀 변화에 따른 결과로 볼 수 있다.

### 4.2 실험 설계

기존 21회 이상 기준에서 6회 이상, 2회 이상으로 빈도 기준을 확장했다.

세 실험 모두 동일한 모델, 검색 방향, Top-5 및 유사도 임계값 0.80을 사용했다.

| 구분 | ge21 | ge6 | ge2 |
|---|---:|---:|---:|
| 빈도 기준 | ≥21 | ≥6 | ≥2 |
| 한국어 용어 | 933 | 3,405 | 8,505 |
| 영어 용어 | 164 | 673 | 2,027 |
| 혼합 표현(제외) | 15 | 28 | 66 |
| 전체 입력 용어 | 1,112 | 4,106 | 10,598 |
| 생성 후보쌍 | 2,573 | 11,510 | 33,414 |
| Mutual best | 81 | 285 | 781 |

빈도 기준을 낮출수록 검색 대상 용어와 생성 후보 수가 증가했다.

특히 ge2는 ge21에 비해 훨씬 많은 후보를 생성했지만, 후보 수 증가가 실제 정답쌍 증가를 의미하지는 않는다.

### 4.3 기존 후보 유지율

ge21에서 생성된 2,573개 후보쌍이 확장된 풀에서도 유지되는지 확인했다.

| 비교 항목 | ge6 | ge2 |
|---|---:|---:|
| ge21 후보 유지 | 1,181 | 678 |
| 유지율 | 45.9% | 26.35% |
| ge21 고유사도 후보 153쌍 중 유지 | 150 | 141 |
| ge21 mutual best 81쌍 중 유지 | 81 | 80 |

검색 대상이 늘어나면 기존 후보가 Top-5 밖으로 밀려날 수 있다.

이는 기존 후보의 유사도 점수가 하락해서라기보다, 더 유사한 경쟁 용어가 검색 풀에 추가되기 때문일 수 있다.

### 4.4 주요 사례

**① 풀 확장으로 새롭게 발견된 후보**

- `야구 ↔ baseball`: ge6 및 ge2
- `1990년대 ↔ 1990s`: ge6 및 ge2
- `비극 ↔ tragedy`: ge6에서 발견

**② 풀 확장 후 누락된 후보**

`비극 ↔ tragedy`는 ge6에서 유사도 약 0.805로 검색됐지만, ge2에서는 Top-5 경쟁으로 후보에서 제외됐다.

이는 단순히 검색 풀을 크게 만드는 것이 항상 유리하지 않다는 것을 보여준다.

**③ 모델이 놓친 번역쌍**

`로드무비 ↔ road movie`는 실제 동일 개념이지만 실험한 풀에서 후보로 검색되지 않았다.

**④ 높은 유사도의 오탐**

`마법 ↔ martial arts`, `재수생 ↔ reincarnation`처럼 유사도 0.80을 넘더라도 동일 개념이 아닌 사례가 존재한다.

### 4.5 중간 결론

- **ge21:** 후보가 적어 검토 부담은 작지만 저빈도 개념 누락 가능성이 높다.
- **ge6:** 검색 범위와 후보 수 사이의 잠정적인 절충안이다.
- **ge2:** 더 많은 저빈도 표현을 탐색할 수 있지만 후보 수가 크게 증가하고 Top-5 경쟁도 심해진다.

현재는 **ge6를 잠정적인 실용 기준으로 고려하고 있으며, 최종 선택은 독립 Recall 평가 이후 결정한다.**

## 5. 독립 Recall 평가 설계

### 5.1 평가가 필요한 이유

E5 후보 수만으로는 검색 품질을 판단할 수 없다.

실제로 존재하는 한영 동일 개념쌍 중 E5가 얼마나 찾아냈는지 확인해야 한다.

이를 위해 독립적인 정답 목록(Gold)이 필요하다.

하지만 E5가 생성한 후보만 검토하여 Gold를 구성하면 E5가 검색하지 못한 정답이 누락된다. 이 경우 실제보다 재현율이 높게 측정될 수 있다.

따라서 **Gold는 E5 검색 결과와 독립적으로 구성하는 것을 원칙으로 한다.**

### 5.2 평가 표본

초기 파일럿은 총 30개 질의로 구성했다.

| 빈도 구간 | 한국어 | 영어 | 합계 |
|---|---:|---:|---:|
| 21회 이상 | 6 | 4 | 10 |
| 6~20회 | 6 | 4 | 10 |
| 2~5회 | 6 | 4 | 10 |
| 합계 | 18 | 12 | 30 |

전체 30개를 바로 평가하지 않고, 우선 5개 질의로 평가 절차를 시험한다.


### 5.3 평가 지표

| 지표 | 평가 내용 |
|---|---|
| 방향별 Recall@5 | 한국어→영어, 영어→한국어 각각의 정답 회수율 |
| 양방향 Recall@5 | 두 방향의 합집합에서 정답 회수율 |
| 최종 후보 Recall | Top-5와 유사도 0.80을 모두 적용한 결과 |
| Hit@5 | 정답을 하나 이상 찾은 질의 비율 |
| Pool Coverage | 정답 표현이 검색 대상 풀에 존재하는 비율 |
| 조건부 Recall | 정답 표현이 풀에 존재할 때의 회수율 |
| Wilson 95% CI | 표본 비율의 불확실성 확인 |

정답을 찾지 못한 원인도 구분한다.

1. **Pool Coverage 실패:** 정답 표현이 검색 대상 용어 풀에 없음
2. **검색 순위 실패:** 정답 표현은 있지만 Top-5 밖으로 밀림
3. **임계값 실패:** Top-5에 포함됐지만 유사도가 0.80 미만

이 구분을 통해 빈도 기준을 넓혀야 하는지, Top-K나 유사도 임계값을 조정해야 하는지 판단할 수 있다.

평가 코드:

- `rank_gold_pairs.py`
- `eval_recall.py`

현재 Gold가 확정되지 않았으므로 재현율 결과는 아직 산출하지 않았다.

## 6. 독립 정답 구성 및 5개 파일럿

### 6.1 라벨링 방식 변경

처음에는 사람이 번역어를 직접 떠올리고 전체 용어 목록에서 검색하는 방식을 설계했다.

하지만 다음과 같은 문제가 있었다.

- 영어 표현에 대한 개인 지식에 따라 판단 품질이 달라짐
- 한국 고유 표현이나 영화 맥락의 판단이 어려움
- 전체 용어 목록을 직접 검색해야 하는 작업 부담
- 정답 탐색과 동일 개념 판정이 한 사람에게 집중됨

따라서 **자동 후보 생성 → AI 의미 판정 초안 → 사람의 제한적 검토** 방식으로 변경했다.

AI가 초안을 작성하더라도 최종 Gold는 검토 상태를 구분해 관리한다.

### 6.2 Wikidata 보조 후보 생성 v1

파일:

`fetch_translation_candidates.py`

5개 파일럿 질의:

- 로보트
- 가정폭력
- christmas
- 파트너
- 북괴공작원

Wikidata의 다국어 레이블과 별칭을 활용해 E5와 독립적으로 후보를 생성했다.

실제 Wikidata 요청 6건을 실행했고 총 31개 후보 행을 생성했다.

그러나 초기 방식에서는 다음 문제가 발견됐다.

- `로보트` 검색에서 `로봇`(Q11012)이 검색되지 않아 `robot` 누락
- `robotics`, `starter Pokémon` 등 의미가 다른 검색 결과 혼입
- Wikidata에 등록되지 않은 표현의 후보 누락

### 6.3 Wikidata 보조 후보 생성 v2

기존 Wikidata 캐시를 재사용하여 추가 요청 없이 개선했다.

주요 개선 사항은 다음과 같다.

- 한국어 표기 변형을 이용한 후보 확장
- `로보트 → 로봇 → robot` 경로 추가
- 비정확 검색 결과를 검토 대상과 분리
- 후보 출처 기록 (`wd_label`, `wd_alias`, `ortho_variant`, `human_seed` 등)
- 언어와 개념 유형을 활용한 명백한 오탐 구분
- 의미적으로 동일한지 자동 확정하지 않음

결과:

| 구분 | 후보 행 |
|---|---:|
| 검토 대상(kept) | 23 |
| 보류(held) | 24 |
| 제외(excluded) | 0 |

v2에서 `robot` 누락은 해결됐지만, `북괴공작원`처럼 Wikidata로 대응 표현을 찾기 어려운 경우는 여전히 남았다.

또한 `in_term_list=False`는 해당 표현이 수집한 용어 목록에 없다는 의미이지, 다른 개념이라는 뜻이 아니다.

예를 들어 `성탄절`은 `christmas`와 동일 개념이지만 용어 목록에는 존재하지 않는다.

| 질의 | AI 초안 | 확인한 대응어 |
|---|---|---|
| 로보트 | HAS_EXACT | robot |
| 가정폭력 | HAS_EXACT | domestic violence |
| christmas | HAS_EXACT | 크리스마스 |
| 파트너 | HAS_EXACT | partner |
| 북괴공작원 | NOT_IN_LIST (낮은 신뢰) | 목록 내 영어 대응어 미확인 |

`domestic abuse`는 중간 신뢰의 추가 후보로 기록했다.

`partnership`은 `파트너`와 동일 개념으로 보지 않았다.

모든 판정은 현재 `llm_draft`이며, 사람 검토 상태는 `UNREVIEWED`다.

**AI 초안은 확정 Gold가 아니다.**

### 6.5 사람 검토 계획


총 19행:

- 불확실한 후보 12행
- 무작위 확인 6행
- `북괴공작원` 1행

사람은 모든 번역쌍을 처음부터 검색하는 대신 AI가 작성한 판단과 근거를 확인한다.

확실하지 않은 경우 `UNSURE`로 유지한다.

AI 초안(`draft_*`)과 사람 검토(`human_*`)는 별도 컬럼으로 관리하며, 사람이 검토한 결과만 확정 Gold에 포함한다.

### 6.6 파일럿의 한계

현재 5개 질의 중 4개는 비교적 쉬운 번역 사례이므로 이 표본만으로 전체 E5 성능을 일반화할 수 없다.

또한 AI 초안이 Wikidata 후보를 확인한 뒤 추가 검색한 결과이므로, 자동 후보 생성기가 놓친 정답을 완전히 독립적으로 측정한 것은 아니다.

향후 필요하다면 후보를 확인하기 전 번역어를 먼저 작성하는 방식과 비교하거나, 더 다양한 난이도의 질의로 평가를 확대할 수 있다.

## 핵심 결론

E5 기반 한영 키워드 후보 탐색과 빈도 기준별 풀 확장 실험을 완료했다. ge21/ge6/ge2 결과의 재현성도 검증했다.

풀을 확장하면 더 많은 표현을 검색할 수 있지만, Top-5 경쟁으로 기존 후보가 누락되고 유사도가 높은 오탐도 발생한다.

따라서 현재는 ge6를 잠정적인 기준으로 두고 있으며, **독립적인 Gold를 통한 Recall 평가를 완료한 후 최종 빈도 기준을 결정할 예정이다.**

현재 가장 우선적인 작업은 5개 파일럿의 사람 검토를 마무리하고 평가에 사용할 정답쌍을 확정하는 것이다.
