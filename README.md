## 구조화 관계 추출 및 장르 엔티티 정규화 (11/15~11/17)

### 1. 구조화된 관계 추출 로직 설계 및 구현

영화·드라마·도서의 구조화된 메타데이터에서 인물 및 원작 관계를 추출하고, 이를 공통 엔티티와 연결하기 위한 파이프라인을 설계함.

**1-1. 관계 추출 범위**

- 인물 관계: 감독(`director`), 배우(`cast`), 각본가(`screenwriter`), 저자(`author`), 원작자(`original_author`)
- 작품 관계: 원작 작품(`original_story`)
- 데이터 출처: TMDb, KMDb, 국가서지·YES24 등 기존 구조화 메타데이터
- `content → entity` 관계를 생성하고, 이후 `entity → content` 역방향 탐색에 활용하도록 설계
- 관계별 원본 출처와 근거를 보존하고, 후보 생성과 DB 적재 단계를 분리

**1-2. 인물명 정규화 및 매칭 로직**

영문 인물명과 한글 인물명의 표기 차이로 인한 매칭 실패를 줄이기 위해 **라이브러리 기반 변환과 코드 기반 규칙을 병행**하는 방식을 설계함.

- 한글 이름은 기본적으로 원형 유지
- 영문 이름은 한국식 이름의 로마자 표기 여부에 따라 규칙 기반 변환 또는 라이브러리 기반 변환 적용
- 성씨 표기 변형, 이름 음절 분리, 특수 표기 등 예외 사례에 대한 규칙 보완
- 변환 결과는 확정된 동일 인물이 아니라 매칭 후보로 취급
- 기존 `entity`의 `PERSON` 데이터와 대조한 뒤 매칭 여부를 검토하도록 설계

**실행 및 검증 결과**

| 항목 | 결과 |
|---|---:|
| 추출한 원천 인물 레코드 | 266,918건 |
| 영문명 정규화 대상 | 14,441건 |
| 규칙 기반 변환 | 8,641건 |
| 라이브러리 기반 변환 | 5,800건 |
| 변환 불필요 | 252,477건 |
| 변환 처리 실패 | 0건 |

초기 30개 사례를 재검증한 결과 28개가 예상 매칭에 부합했으며(93.3%), 나머지 2개 사례의 표기 규칙을 보완함.

후속 그룹화 작업에서는 266,918건을 188,465개 그룹으로 정리함. 이 과정에서 원형 유지 179,823개 그룹, 변환 후보 8,037개 그룹, 불일치 검토 대상 325개 그룹을 확인함.

**결정 사항**

단일 라이브러리의 변환 결과에 의존하지 않고, 한국인 이름의 표기 특성을 반영한 규칙과 라이브러리를 병행하기로 결정함. 변환 처리 및 표본 검증을 완료했으며, 자동 변환 결과를 곧바로 동일 인물로 확정하지 않고 별도 매칭 검토 단계를 유지함.

현재는 후보 추출·정규화·그룹화 및 엔티티 매칭 후보 생성 단계를 분리하여 구현 중이며, DB 자동 적재 전 검증 구조를 유지함.

### 2. KMDb 크레딧 데이터 수집 방식 비교 및 API 수집 결정

감독·배우·각본가의 인물 ID 및 영문명, 원작자·원작 정보를 확보하기 위해 KMDb 크레딧 데이터를 검토함.

기존 CSV 파일 `영화상세정보_크레딧_1129.csv`와 KMDb API 직접 수집 결과를 비교하여 데이터 확보 방식을 결정함.

**2-1. CSV 데이터 검증**

| 항목 | 결과 |
|---|---:|
| CSV 수록 영화 | 4,720편 |
| DB 매칭 영화 | 4,651편 |
| CSV 내부 DB 매칭률 | 98.54% |
| 전체 DB 영화 대비 커버리지 | 4.71% |
| 매칭된 크레딧 레코드 | 79,647건 |
| ID가 있는 크레딧 | 33,938건 |

CSV는 수록 영화의 DB 매칭률은 높았으나, 전체 영화 DB 98,820편 중 4.71%만 포괄하여 구조화 관계 확장에 활용하기에는 범위가 제한적이었음.

**2-2. KMDb API 수집 및 검증**

KMDb API를 통해 영화 상세정보와 크레딧을 직접 수집하고, 수집 결과의 무결성 및 기존 DB 매칭 여부를 검증함.

| 항목 | 결과 |
|---|---:|
| 수집 JSON 파일 | 82개 |
| 수집 영화 | 41,000편 |
| 고유 영화 ID | 41,000개 |
| 중복·누락·수집 실패 | 0건 |
| DB 매칭 영화 | 37,922편 |
| 수집 데이터의 DB 매칭률 | 92.49% |
| 전체 DB 영화 대비 커버리지 | 38.37% |

크레딧별 인물 ID 확보 비율은 감독 40.80%, 배우 35.82%, 각본가 55.68%로 확인됨.

원작·원안 관련 정보도 추가로 확인함.

- 원작·원안 관련 크레딧: 2,085건
- 해당 영화: 1,753편
- DB 매칭 영화: 1,697편
- `staffEtc`에서 원작 관련 정보가 확인된 영화: 446편
- 원작 관련 인물 ID가 확보된 크레딧: 696건

**2-3. 최종 결정: CSV 대신 KMDb API 활용**

API 수집 데이터는 CSV보다 DB 기준 영화 커버리지가 약 8.1배 높았으며(4.71% → 38.37%), 수집 데이터의 중복·누락·실패도 확인되지 않았음.

또한 프로젝트에서 필요한 인물 ID, 영문명, 원작·원안 관련 정보를 함께 확보할 수 있어, 구조화 관계 추출의 주요 데이터 소스로 API 수집 결과를 사용하기로 결정함.

단, API에서도 모든 인물의 ID가 제공되는 것은 아니므로, ID가 없는 인물에 대해서는 앞서 설계한 인물명 정규화·매칭 로직을 보조적으로 활용함.

### 3. 장르 엔티티 추출을 위한 출처별 매핑 규칙 설계

KMDb와 TMDb에서 사용하는 장르명이 서로 다르거나, 유사한 명칭이 서로 다른 작품군에 부여되는 문제를 해결하기 위해 장르 표준화 규칙을 설계함.

**3-1. 설계 방향**

- `entity.entity_type`에 `GENRE` 추가
- `content_entity.link_role`에 `genre` 추가
- 장르는 계층 구조 없이 동등한 엔티티로 관리
- 원본 장르는 `movie_detail.genres`에 그대로 보존
- 출처별 장르명을 표준 장르로 매핑한 뒤 `entity`와 `content_entity`에 적재
- 동일 콘텐츠에 같은 표준 장르가 여러 출처에서 부여되더라도 관계는 한 건만 생성하고, 출처별 근거는 별도로 보존

**3-2. 장르 중복률 분석**

`movie_detail.genres`를 기준으로 장르별 콘텐츠 집합을 추출하고, 공통 작품 수와 중복률, Jaccard 유사도를 계산함.

주요 결과는 다음과 같음.

| 비교 장르 | Jaccard | 결정 |
|---|---:|---|
| KMDb 사극 / 시대극 | 100% | 통합 |
| KMDb 반공 / 분단 | 100% | 통합 |
| KMDb 멜로 / 로맨스 | 100% | 통합 |
| KMDb 범죄 / 느와르 | 3.47% | 분리 |
| KMDb 범죄 / 갱스터 | 3.23% | 분리 |
| KMDb 사회 / 사회물(경향) | 0.18% | 분리 |
| KMDb 인물 / 전기 | 0.37% | 분리 |

KMDb와 TMDb의 로맨스 관련 분류는 두 출처에 모두 등록된 영화를 대상으로 추가 비교함.

| 비교 장르 | Jaccard |
|---|---:|
| KMDb 멜로드라마 / TMDb 로맨스 | 30.71% |
| KMDb 멜로 / TMDb 로맨스 | 29.67% |

두 비교 결과의 차이는 크지 않으나, KMDb 내부에서 `멜로`와 `멜로드라마`가 서로 다른 작품군으로 분류되는 점을 고려하여 다음 매핑을 채택함.

**3-3. 주요 장르 매핑 규칙**

| 원본 장르 | 표준 장르 |
|---|---|
| KMDb 사극, 시대극 | 시대극 |
| KMDb 반공, 분단 | 분단 |
| KMDb 멜로, 로맨스 | 멜로 |
| KMDb 멜로드라마 | 로맨스 |
| TMDb 로맨스 | 로맨스 |
| KMDb 코메디 / TMDb 코미디 | 코미디 |
| KMDb 공포(호러) / TMDb 공포 | 공포 |
| KMDb 어드벤처 / TMDb 모험 | 모험 |
| KMDb 뮤직 / TMDb 음악 | 음악 |

범죄·느와르·갱스터, 액션·무협·활극, 사회·인권·계몽 등은 의미와 실제 분류 차이를 고려하여 독립 장르로 유지함.

**3-4. DB 적재 구조**

`movie_detail.genres → 장르 매핑 → entity(GENRE) → content_entity(genre) → content_entity_evidence`

- 기존 테이블을 활용하며 별도의 장르 테이블은 생성하지 않음
- `source_fact` 기반 관계 및 `metadata` 근거를 사용
- 중복 관계 방지 및 원본 출처 보존
- 적재 코드 작성 후 DB 반영 전 검증 단계 진행

### 4. 작업 결과 및 후속 진행

**완료·검증**

- 구조화된 인물·원작 관계 추출 범위 및 처리 구조 설계
- 인물명 정규화에 라이브러리와 코드 기반 규칙 병행
- 인물명 변환 처리 및 표본 검증, 그룹화 결과 확인
- KMDb 크레딧 CSV와 API 수집 데이터 비교
- 데이터 커버리지와 수집 무결성 검증을 근거로 API 활용 결정

- `GENRE` 엔티티 타입과 `genre` 관계 역할 추가

**후속 작업**

- 인물명 매칭 후보의 검토 및 확정 엔티티 적재
- KMDb API 크레딧을 활용한 감독·배우·각본가·원작자 관계 생성
- 원작 작품(`original_story`)의 명시적 근거 확인 및 관계 적재
- 장르 엔티티·콘텐츠 관계·근거 적재 코드의 실제 DB 검증
- 구조화 관계와 기존 후보 선정 로직의 통합
- 도서 키워드 확장

**핵심 진행 내용:** 구조화 관계 추출에 필요한 인물 식별 및 원작 데이터 확보 방식을 실험 결과에 근거해 결정하고, 출처별 장르 표준화 규칙을 수립하여 관계 기반 탐색을 위한 데이터 적재 기반을 마련함.
